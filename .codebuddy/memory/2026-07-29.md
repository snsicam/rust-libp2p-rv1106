# 2026-07-29

## Android Studio 在 Wayland 下无法启动模拟器（再发，已落地持久修复）
- 现象同 07-28：当前会话 `XDG_SESSION_TYPE=wayland`，Studio 自带模拟器走 Wayland EGL 后端失败、起不来；`run_emulator.sh` 能跑（内建 `export QT_QPA_PLATFORM=xcb` + `-gpu host`）。
- Studio 位置：`/opt/android-studio`（脚本 `/opt/android-studio/bin/studio.sh`），`/usr/bin/studio` 是 JetBrains 二进制 launcher。`PATH` 中 `/usr/local/bin` 在 `/usr/bin` 之前。
- **已落地持久修复**：在 `~/.bashrc` 追加 `alias studio='QT_QPA_PLATFORM=xcb /usr/bin/studio'`（无需 sudo，仅影响 studio 命令、不动全局 env，不影响其它 Wayland Qt 程序）。
  - 立即生效命令：`QT_QPA_PLATFORM=xcb studio &`；新终端直接 `studio` 即自动套用；当前终端 `source ~/.bashrc` 刷新。
- 局限：bash 别名**只对命令行 `studio` 生效**；若用户用**桌面图标/任务栏收藏**启动 Studio（走 .desktop 启动器），别名不生效，仍需另做 `~/.local/share/applications/android-studio.desktop`（Exec 加 `env QT_QPA_PLATFORM=xcb`）。或 GDM 登录选 "Ubuntu on Xorg" 整会话转 X11 最彻底。

## 确认 (b)：Studio 弹出但点运行起不来（模拟器 disconnected）
- 用户确认：Studio 窗口弹出了，但点 Run 模拟器起不来。
- 根因定位：Studio 点运行时加载了**损坏快照** `default_boot`（日志 `Failed to load snapshot 'default_boot'` + `disconnected while waiting for 'ONLINE'`）；而 `run_emulator.sh` 用 `-no-snapshot-load` 跳过快照，故脚本能起、Studio 不能——正是两者差异。
- 方案 A（立即可用）：终端 `bash /home/song/samba/work/p2p/rust-libp2p/p2p-camera/scripts/run_emulator.sh` 起模拟器（~20s boot），Studio 内 Run 选已在线 `emulator-5554`。
- 方案 B（让 Studio 点运行也能用）：`rm -rf ~/.android/avd/Medium_Phone_API_34.avd/snapshots` 清坏快照；Device Manager 对该 AVD `Wipe Data`；Boot option 改 `Cold boot`（避免再存/载损坏 Quickboot 快照）。可把 `fastboot.forceColdBoot=yes` 写进 AVD config.ini 固化。
