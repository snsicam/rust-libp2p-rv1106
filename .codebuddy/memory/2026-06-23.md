### 关键设计决策
- **current_thread runtime**: SDL2 要求事件循环在主线程，tokio `current_thread` flavor 保证 swarm + SDL 渲染在同一线程
- **feature flag**: `player` feature 控制 SDL/ffmpeg 依赖，不启用时 viewer_cli 仍可文件输出模式编译
- **YUV 平面拷贝**: `frame.data(0).to_vec()` 避免 `self.yuv_frame` 和 `self.texture` 的借用冲突
- **swscale 回退**: 非 YUV420P 格式自动用 `ffmpeg::software::scaling` 转换
- **ffmpeg-next 版本**: 用 "6" 匹配 Ubuntu 24.04 的 ffmpeg 6.1.1

### 编译踩坑记录 (Linux x86_64, Ubuntu 24.04, ffmpeg 6.1.1)

**坑1: ffmpeg-next 不能禁用 default features**
- `default-features = false, features = ["codec", "software-scaling"]` → 编译失败
- 原因: ffmpeg-next 6.1.1 的 `codec/packet.rs`、`codec/video.rs`、`software/mod.rs` 内部硬编码 `use format` / `::format::Pixel`
- 解决: 保留默认 features，安装全部 dev 包: `sudo apt install libavcodec-dev libavformat-dev libavutil-dev libswscale-dev libswresample-dev libavfilter-dev libavdevice-dev`

**坑2: bindgen 找不到 `limits.h`**
- 错误: `/usr/include/limits.h:124:16: fatal error: 'limits.h' file not found`
- 原因: libclang 默认不搜索 GCC 内部 include 目录 (`/usr/lib/gcc/x86_64-linux-gnu/13/include`)
- 解决: `export BINDGEN_EXTRA_CLANG_ARGS="-I$(gcc -print-file-name=include)"` (已内置到 play_viewer.sh)

**坑3: 创建 video decoder 的正确 API 路径**
```rust
// ❌ 错误: Context::for_decoder(codec) 不存在
// ❌ 错误: codec.decoder().video() — decoder() 返回 Option<Codec>, 没有 .video()
// ❌ 错误: codec.video() — 返回 codec::Video (编码器信息), 不是 decoder::Video

// ✅ 正确:
let codec = ffmpeg::decoder::find(ffmpeg::codec::Id::HEVC)?;
let decoder = ffmpeg::codec::Context::new()
    .decoder()           // Context → Decoder
    .open_as(codec)?     // 用指定 codec 打开 → Opened
    .video()?;           // Opened → decoder::Video
```

**坑4: sdl2 Texture 需要 lifetime 参数**
- `Texture<'a>` 绑定到 `TextureCreator`，但 Creator 是 Canvas 的方法返回的临时引用
- 解决: `unsafe { std::mem::transmute::<Texture<'_>, Texture<'static>>(tex) }`
- 安全前提: struct 字段声明顺序保证 texture 在 canvas 之前 drop

**坑5: sdl2 返回多种错误类型**
- `String` / `IntegerOrSdlError` / `TextureValueError` / `UpdateTextureYUVError`
- 解决: 泛型 helper `fn map_sdl<T, E: ToString>(r: Result<T, E>, ctx: &str) -> Result<T>`

**坑6: ffmpeg-next 需要 `traits::Decoder` trait**
- `codec.decoder()` 方法来自 `ffmpeg_next::codec::traits::Decoder` trait，需要显式 import

**坑7: scaler.run() 需要 &mut**
- `self.scaler.as_ref()` 返回 `&`，`run()` 需要 `&mut`
- 解决: `self.scaler.as_mut().unwrap()`

## 修复: gateway 启用音频时 segfault (下午)

### 现象
```
./gateway --relay ... --enable-audio
[rk_camera] audio init: 16000Hz
Segmentation fault (core dumped)
```
段错误发生在 `rk_audio_init` 打印 "audio init" 之后、打印 "audio initialized" 之前。

### 根因
- `main.rs` 中视频源 `RkVideoSource::spawn()` 是**延迟启动**的 (线程内 `start_rx.recv()` 等第一个 viewer 连接才触发 `rk_camera_init`)
- 音频源 `RkAudioSource::spawn()` 是**立即运行**的 (线程内直接调 `rk_audio_init`)
- `rk_audio_init` 没有调用 `RK_MPI_SYS_Init()` (只有 `rk_camera_init` 调了)
- 结果: `RK_MPI_AI_SetPubAttr` 等 AI 函数在 MPP 系统未初始化的情况下被调用 → segfault
- 参考 rkipc `rkipc_ai_init()` (rv1106/audio.c:230) 也不调 SYS_Init, 因为 rkipc 主流程已先调过

### 修复 (gateway/src/rk_camera.c)
1. 新增 `static volatile int g_sys_init_count = 0;` 引用计数
2. 新增 `ensure_sys_init()` — 首次调用执行 `RK_MPI_SYS_Init()`, 计数 +1
3. 新增 `maybe_sys_exit()` — 计数 -1, 归零时调用 `RK_MPI_SYS_Exit()`
4. `rk_camera_init` / `rk_audio_init` 头部都调 `ensure_sys_init()`
5. `rk_camera_deinit` / `rk_audio_deinit` 尾部都调 `maybe_sys_exit()`

### 教训
RV1106 SDK 的 MPP 系统初始化 (`RK_MPI_SYS_Init`) 必须在任何 `RK_MPI_*` 调用之前完成。当多个子系统 (camera/audio) 独立 init/deinit 时, 需要引用计数共享 SYS_Init/Exit, 不能假设某个子系统总是先初始化。

## DCUtR 直连优化 (下午)

### 问题根因
Gateway 和 Viewer 都已挂载 `dcutr::Behaviour`，但**都没有 `listen_on` 本地 QUIC/TCP 地址** → DCUtR 无法触发 hole punch（没有本地 UDP socket 可用于打洞）。这是 DCUtR 不工作的根因。

### DCUtR 工作原理 (确认)
1. **双方都必须 `listen_on` 本地 QUIC+TCP 地址** (`examples/dcutr/src/main.rs:111-116`) — hole punch 需要本地 socket
2. DCUtR 在 circuit 连接建立后**自动触发**（reservation 持有方=Gateway 发起），无需显式调用
3. `libp2p_stream::Control` 是 `Clone` 的，`open_stream(&mut self, ...)` — 可在 select! 分支中调用
4. DCUtR 成功后建立直连 connection，旧 circuit 连接保留但空闲

### 改动文件
1. **`gateway/src/main.rs`**:
   - dial relay 前新增 `listen_on("/ip4/0.0.0.0/udp/0/quic-v1")` + `listen_on("/ip4/0.0.0.0/tcp/0")`
   - 事件循环加 `NewListenAddr` 打印 + `ConnectionEstablished` 的连接方向 (dialer/listener)

2. **`mobile-core/examples/viewer_cli.rs`**:
   - dial relay 前新增本地 QUIC+TCP 监听
   - video/audio 接收 task 保存 `AbortHandle` (用于迁移时 abort 旧 task)
   - `tx`/`audio_tx` 改为 `clone()` 给 task (保留原 sender 供迁移复用)
   - DCUtR 成功事件分支 (`if !direct_upgraded` 守卫):
     - 直连上 `open_stream` 重开 video stream → abort 旧 circuit task → spawn 新 task
     - 直连上重开 audio stream → 同样迁移
     - `direct_upgraded = true` 防重复
   - DCUtR 失败: 打印 "staying on relay circuit"
   - Summary 加 `Direct connection (DCUtR): YES/NO`

### Stream 迁移机制
- DCUtR 成功 → `dcutr::Event { result: Ok(connection_id) }` 携带直连 ConnectionId
- Viewer 在直连上 `open_stream` → libp2p 优先选最新建立的直连 connection
- abort 旧 receive task → 旧 stream drop → Gateway 侧 `stream_video_to_viewer` 写入失败自然结束
- 新 stream: Gateway 重新发 init NALs (VPS/SPS/PPS) → viewer 解码器重新初始化 → 等下一个 IDR 显示
- 期间有短暂画面跳动 (P 帧解码失败被 ffmpeg 丢弃)，可接受
- 旧 circuit 连接保留 (relay reservation 需要)，空闲不占带宽

- 需在 Ubuntu 上 `cargo build` + 实测 DCUtR hole punch 是否成功

## DCUtR + POC 修复 (下午实测后)

### 实测结果 (Ubuntu, RV1106 真实摄像头)
- 视频+音频 via relay circuit: ✅ 正常播放
- DCUtR: ❌ 失败 — "Inbound stream error: IO error", Summary 显示 NO (relay circuit)
- HEVC POC: ❌ "Could not find ref with POC 41/45/16/10/2" — 丢帧导致

### DCUtR 失败根因分析
- Gateway 通过 **TCP** 连接 relay (`/ip4/192.168.1.120/tcp/4001/...`)
- identify 只观察到 Gateway 的 TCP 地址 → DCUtR 只有 `/ip4/192.168.1.107/tcp/46312` 可用
- Gateway 的 QUIC listen 地址 (`0.0.0.0:随机端口`) 从未被任何节点 observe → 永远不会成为 external address candidate
- TCP hole punch 不可靠 → "Inbound stream error: IO error"
- **修复**: 改用 QUIC 连接 relay: `--relay /ip4/192.168.1.120/udp/4001/quic-v1/p2p/...`
  - relay-server 已监听 QUIC port 4001
  - Gateway 通过 QUIC 连接 relay → identify 观察 QUIC 地址 → DCUtR 有 QUIC 地址 → UDP 打洞
  - libp2p QUIC transport 会复用 listen socket 拨号, 所以 observed 地址 = listen 地址

### HEVC POC 错误根因分析
- Viewer 只收到 3 fps (摄像头输出 25fps → ~88% 丢帧)
- 瓶颈: 软件 H.265 解码 2304x1296 很慢 → mpsc (cap 60) 填满 → stream read 阻塞 → broadcast (cap 100) 溢出 → Lagged → 丢帧 (含 IDR)
- IDR 被丢弃后, 同 GOP 后续 P 帧无法解码 → "Could not find ref with POC X"

1. **`gateway/src/rk_video_source.rs`**:
