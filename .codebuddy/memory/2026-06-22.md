## Bug Fix: relay-server Status::Disable 导致 reservation 被拒

- **File**: `p2p-camera/relay-server/src/behaviour.rs`
- **Root cause**: `relay::Behaviour::new()` 默认 `Status::Disable`。Relay 需 confirmed external address (来自 identify) 才自动 Enable。Gateway 连上后立即请求 reservation，此时 relay 还没 identify → handler 用 `DeniedUpgrade` → hop 协议协商失败 → "Failed to get Reservation."
- **Fix**: 显式 `relay.set_status(Some(relay::Status::Enable))`

## Key Learning: libp2p relay circuit limits

- `max_circuit_bytes: 0` = 无限 (非 0 字节)
- `max_circuit_bytes > 0` = 限制总字节数，超限 relay 关闭 circuit
- 默认 128 KiB 仅适合轻量 relay，视频流必须设 0 或大值
- 限制在 `copy_future.rs` 中 data transfer 时执行，非连接建立时

## Bug Fix: split_h265_nal_units 只找 4 字节 start code 导致播放失败

- **File**: `p2p-camera/gateway/src/media_source.rs`
- **Problem**: 只查找 4 字节 start code (0x00000001)，但 H.265 Annex B 允许 3 字节 (0x000001)。ffmpeg 输出中 VPS/SPS/PPS/IDR 用 4 字节，帧内 NAL 用 3 字节。3 字节 start code 处不分帧 → 多个 NAL 合并成一个"unit" → viewer 写出的文件 NAL 边界错乱 → 解码器无法解析 → "播放无视频"
- **Fix**: split 函数同时识别 3 字节和 4 字节 start code

## Bug Fix: viewer 错过 VPS/SPS/PPS 导致 "PPS id out of range"

- **File**: `p2p-camera/scripts/run_test.sh` + `p2p-camera/gateway/src/media_source.rs` + `p2p-camera/gateway/src/main.rs`
- **Problem**: VPS/SPS/PPS 只在文件开头出现一次（或 repeat-headers 的 IDR 前）。Gateway 启动后立即开始播放，viewer 延迟连接（需 relay+circuit+stream open）后只收到 P 帧，没有 VPS/SPS/PPS → 解码器 "PPS id out of range: 0" → 播放无视频
- **Fix 1 (ffmpeg)**: 添加 `repeat-headers=1` x265 参数，每个 IDR 关键帧前重复 VPS/SPS/PPS
- **Fix 2 (duration)**: 30s → 50s，更多关键帧机会
- **Fix 3 (NAL type detection)**: `media_source.rs` 添加 `nal_type()` 函数，基于实际 NAL header 判断关键帧 (IDR=19/20)，替换不准确的 `frame_count % 50 == 0`
- **Fix 4 (--regen flag)**: `run_test.sh` 添加 `--regen` 选项强制重新生成视频
- **Fix 5 (param sets cache + init send) — 核心修复**: `FileVideoSource` 缓存最新 VPS/SPS/PPS 到 `Arc<Mutex<Option<Vec<Vec<u8>>>>>`。新 viewer 连接时 gateway 先发送缓存的参数集，再继续发送实时帧。这是真实摄像头场景的标准做法（viewer 随时连接都能立即解码）
- **H.265 NAL header**: 2 bytes, `nal_unit_type = (byte0 >> 1) & 0x3F`。类型: 32=VPS, 33=SPS, 34=PPS, 19=IDR_W_RADL, 20=IDR_N_LP, 1=TRAIL_R

## Bug Fix: 按帧头发送 + access unit 分帧

- **Problem**: 视频有裂痕/马赛克，"Could not find ref with POC"。两个问题叠加：
  1. 按 NAL unit 分帧（应按 access unit）— 一帧的多个 slice NAL 被拆成独立 packet，时序错乱
  2. Gateway 启动后立即播放，viewer 连接时已在文件中间，错过开头的关键帧
- **Fix 1 (access unit 分帧)**: `split_h265_access_units()` 按帧分组 NAL。AU 边界判断: VPS(32)/SPS(33)/PPS(34)/IDR(19/20) 或 slice NAL 的 `first_slice_segment_in_pic_flag` (NAL header 后第3字节 bit 7)
- **Fix 2 (AU 含 start code)**: 每个 AU 是完整字节流 (含 4 字节 start code)，viewer 直接写入文件
- **Fix 3 (触发式播放)**: `FileVideoSource::spawn` 返回 `(JoinHandle, Sender<()>)` 触发器。Gateway 在第一个 viewer 连接时 `send(())` 触发视频源从文件头开始播放。这样接收文件 = 源文件前 N 秒，便于对比
- **Fix 4 (init NALs)**: 新 viewer 连接时先发送缓存的 VPS/SPS/PPS（加 start code），让 viewer 立即能解码
