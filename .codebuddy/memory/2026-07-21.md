## 修复 device-cam rv1106 交叉编译链接错误 (undefined reference)

- **现象**: `./p2p-camera/scripts/build_device_cam.sh rv1106` 链接阶段报 16 个 `undefined reference`：
  `rk_param_get_int/set_int/get_string/set_string`、`rk_isp_get/set_{contrast,brightness,saturation,sharpness,hue}`、`rk_system_reboot/factory_reset`。
- **根因**: `device-cam/src/rk_video_source.rs` 新增控制通道 FFI 声明 (`extern "C"`)，但 C 侧 `rk_camera.c` 未实现这些函数。
- **修复**: 在 `rk_camera.c` 末尾 (getauxval stub 之前) 补全实现：
  - `rk_isp_*`: cam_id 忽略，转调已有 `rk_camera_get/set_acp_param(RK_CAM_ACP_*)` 与 `rk_camera_get/set_sharpness`。
  - `rk_param_*`: 简易 INI key=value 文件持久化，文件 `/userdata/device-cam.ini`；`param_read_raw`/`param_write_raw` 整文件重写，`pthread_mutex` 保护；`get_string` 返回静态缓冲区 (Rust 侧调用后立即拷贝，单任务串行安全)。
  - `rk_system_reboot` = `sync()+system("reboot")`；`rk_system_factory_reset` = 删 INI + reboot。
- **结果**: `build_device_cam.sh rv1106` 编译通过 (仅剩 14 个 warning)。

## 清理 device-cam 与 viewer 的编译警告 (14 + 11 → 0)

- **device-cam (14 warnings)**:
  - 4 处 `unnecessary unsafe block`：在 `rk_video_source.rs` 的 `get/set_encoder_config`、`get/set_system_config` 中，FFI 调用已封装进安全的 `param_*` 辅助函数，外层 `unsafe {}` 多余，已删除。
  - 10 处 `dead_code`：`Behaviour::new`(behaviour.rs)、`config.rs` 的 `enabled_streams`/`StreamType`/`from_chn_id`/`name`、`net_diag.rs` 的 `RestrictedCone` 变体/`NatDiagnosis`/`DcutrPrediction` 字段/`set_force_4g`/`observed_history_is_empty`/`should_skip_dcutr`、`rk_video_source.rs` 的 `request_idr_all`/`rk_camera_request_idr_all`。均为预留 API，统一加 `#[allow(dead_code)]`。
- **viewer / media_viewer.rs (11 warnings)**: 5 个只写不读的调试变量 `audio_count`/`direct_upgraded`/`direct_via_lan`/`local_nat_type`/`remote_nat_hint` 加 `_` 前缀；`enable_dcutr` 去掉 `mut` 并删除 DcutrBackoff 分支中无效赋值 (`bool` 为 Copy，构造时已传入 `new_with_options`，该赋值永不被读)。
- **结果**: 两个构建脚本均零 warning 通过。

## 修复 device-cam rv1106 C 编译错误 (static declaration follows non-static declaration)

- **现象**: `build_device_cam.sh rv1106` 报 6 个 C error：`rk_camera.c` 中 `rk_camera_set_chn_config`(~594) 调用了 `get_codec_type`/`get_rc_mode`/`get_rc_quality`/`get_profile`/`get_gop_mode`/`get_mirror`，但这些 `static` 函数定义在文件末尾 (~1043-1082)，使用点在前、定义在后 → 编译器将首次使用视为隐式非 static 声明，随后 `static` 定义与之冲突。
- **根因**: 这些辅助函数定义在调用点之后，缺少前向声明。 (`get_aenc_codec` 在 945 调用/909 定义，顺序正常，无此问题。)
- **修复**: 在 `rk_camera.c` 头文件 include 之后、常量定义之前，新增这 6 个函数的前向声明 (`static int get_codec_type(const char *codec_str);` 等)。
- **结果**: `build_device_cam.sh rv1106` 编译通过，且无任何 warning/error 残留。
- **提示**: 后续若在 `rk_camera.c` 新增 `static` 辅助函数并被其定义之前的代码调用，需同步加前向声明，否则会重现该错误。
