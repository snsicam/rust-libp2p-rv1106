## Android 模拟器：Studio 起不来但 run_emulator.sh 能起 (GPU/Wayland)
- 现象：`p2p-camera/scripts/run_emulator.sh` 能启动模拟器，Android Studio 起不来。
- 根因：脚本 `run_emulator.sh:100` 硬写 `-gpu swiftshader_indirect`（软件渲染，绕开 GPU）；Studio 默认走 host GPU 模式，而本机会话是 **Wayland**（Ubuntu GNOME, `XDG_SESSION_TYPE=wayland`），模拟器 Qt 在 Wayland 下创建 EGL 上下文失败 → 启动失败/黑屏。
- 硬件条件其实满足：Intel UHD 630 + Mesa(EGL/GLES/GBM 都在) + `/dev/dri/renderD128` 有 ACL `user:song:rw-`（用户能访问 render 节点，无需加 render/video 组）。KVM 也在。
- 已验证：用 `QT_QPA_PLATFORM=xcb`（强制 X11 后端）+ `-gpu host` 启动，模拟器 20s 内 boot 完成，日志 `hasSufficientHwGpu: Ok` / `supportsNativeGLES=1`。**GPU 加速完全可用**，Wayland 是唯一阻碍。
- 修复（已做）：把 AVD `~/.android/avd/Medium_Phone_API_34.avd/config.ini` 改为 `hw.gpu.enabled=yes` + `hw.gpu.mode=host`。
- 让 Studio 用 GPU 的两种方式：
  1. （推荐）GDM 登录选 **"Ubuntu on Xorg"**，整会话 X11，Studio 直接 GPU 加速。
  2. （保留 Wayland）用 `QT_QPA_PLATFORM=xcb studio &` 启动 Studio，让其派生的模拟器走 X11 后端。**勿**把该变量写进全局 `.profile`（会影响其它 Wayland Qt 程序）。
- 可选：脚本若要也用 GPU，去掉 `run_emulator.sh:100` 的 `-gpu swiftshader_indirect` 即可（AVD 已是 host）。

- 已做（本轮）：`run_emulator.sh` 启动模拟器前 `export QT_QPA_PLATFORM=xcb`，并把 `-gpu swiftshader_indirect` 改为 `-gpu host`，脚本现已用 GPU 加速。验证：日志 `Found physical GPU 'Intel(R) UHD Graphics 630'` + `hasSufficientHwGpu: Ok` + `ASTC LDR emulation mode: Gpu` + guest `hwui.renderer=skiagl`；无 SwiftShader/software fallback 行 → 确实走 GPU。
- 注意：日志里 `ERROR | Your GPU cannot be used for hardware rendering. Consider using software rendering.` 是**良性告警**（探测老式 GL 路径失败），模拟器随后用 Vulkan/ANGLE 走 Intel GPU，并非真回退软件渲染。判据：无 `SwiftShader` / `fallback to software` 行 + 有 `ASTC LDR emulation mode: Gpu` 即表示 GPU 生效。

## 图像参数范围核对 (UI 0-100 vs 底层)
- 用户要求图像参数 UI 统一 0-100，并担心"底层可能需要转换"。
- 核对结论：**底层契约本来就是 0-100，且 C 层已做转换，JSON 边界无需再转换**。
  - `device-cam/src/rk_camera.c:1640` `rk_camera_set_acp_param`：UI 值 `×2.55` → ISP 原生 0-255 写硬件。
  - `rk_camera.c:1697` `rk_camera_get_acp_param`：硬件 0-255 `/2.55` → 0-100 返回。锐度：`0-100/100` ↔ `percent 0-1`。
  - `device-cam/src/rk_video_source.rs:888-902`：set 端对 brightness/contrast/saturation/sharpness 全部校验 `0<=v<=100`，越界报错。
  - viewer (`mobile-core/examples/media_viewer.rs:1675-1678`) 图像参数也是 0-100 clamp，一致。
- 发现的真实 bug：原 UI 把亮度/对比度/饱和度文案写成 `(-100~100)` 且输入框是 `numberSigned`（可输负数），会触发底层 "out of range 0-100" 报错导致下发失败。
- 已修复（3 处）：
  1. `strings.xml`：cfg_brightness/cfg_contrast/cfg_saturation 文案 `(0~100)`（锐度本就是 0~100）。
  2. `layout/dialog_device_config.xml`：edit_brightness/edit_contrast/edit_saturation 的 `inputType` 由 `numberSigned` → `number`（禁负）。
  3. `MainActivity.kt:584-587`：apply 时四个图像参数 `coerceIn(0,100)` 防御 clamp（fetch 端无需改，底层返回已是 0-100）。
