  - libp2p-stream for continuous frame transmission
  - Custom binary frame protocol (not RTP)
  - RV1106 Rust cross-compile to ARM
  - Mobile native APP with FFI to Rust core

## User Requirements Clarified (Updated)

- Camera: RV1106 chip, H.265 HW encode, **SDK API direct read (NOT RTSP)**
- Audio: SDK API direct read PCM/AAC alongside video
- Mobile: Native APP (Android/iOS), not browser
- Goal: P2P to save relay bandwidth, not pure relay
- TURN: NOT needed — libp2p Relay Circuit provides equivalent functionality for QUIC

## Key Build Issues Encountered & Fixed

1. p2p-camera initially declared own [workspace] → removed, merged into parent workspace
2. tokio workspace dep uses default-features=false → p2p-camera crates need features=["full"] override
3. Missing deps in parent workspace: anyhow, serde, serde_json, clap, crossbeam-channel → inlined in sub-crates
4. proto crate root must be `src/lib.rs` (not mod.rs)
5. StreamProtocol is in libp2p-swarm, not libp2p-stream
6. relay::client::Behaviour must be obtained from SwarmBuilder callback (not constructed manually)
7. IncomingStreams doesn't impl FusedStream → use `.next()` not `.select_next_some()`
8. tracing-subscriber needs features=["env-filter"]
9. tokio::broadcast::Sender uses `.subscribe()` (not `.resubscribe()`)
