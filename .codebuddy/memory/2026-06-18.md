## Bug Found & Fixed: gateway viewer_listeners kill_tx overwrite

- **File**: `p2p-camera/gateway/src/main.rs`
- **Problem**: `viewer_listeners: HashMap<PeerId, oneshot::Sender<()>>` keyed by PeerId. When same viewer opens both video + audio streams, audio accept overwrites video's kill_tx → drop → video stream task receives `Canceled` → video stream ends prematurely.
- **Fix**: Removed unused kill mechanism entirely (YAGNI — kill signal was never actually sent, only inserted). Removed `viewer_listeners` HashMap, `HashMap` import, kill_tx/kill_rx from both `stream_video_to_viewer` and `stream_audio_to_viewer`. Tasks now end naturally on stream error/EOF. Added `stream.close().await` at task end.
- Would have blocked audio testing; video-only test (viewer_cli) was unaffected.

## Bug Found & Fixed: relay-server Status::Disable 导致 reservation 被拒

- **File**: `p2p-camera/relay-server/src/behaviour.rs`
- **Problem**: `relay::Behaviour::new()` 默认 `status: Status::Disable`，`auto_status_change: true`。Relay 只有在有 confirmed external address 时才自动 Enable。但 external address 来自 identify 的 observed_addr —— 需要客户端先连上来才触发。Gateway 连上后立即请求 reservation，此时 relay 还没完成 identify → handler 用 `DeniedUpgrade` → hop 协议协商失败 → `ReserveError::Unsupported` → "Failed to get Reservation."
- **Fix**: 在 `Behaviour::new()` 中显式调用 `relay.set_status(Some(relay::Status::Enable))`。专用 relay server 不依赖 external address 自动检测。
- **Key learning**: libp2p relay handler 的 `listen_protocol()` 根据 status 返回不同 upgrade：Enable 用 `ReadyUpgrade`，Disable 用 `DeniedUpgrade`（协议协商直接失败）。handler 在 connection 建立时创建，status 锁定。后续 `reconfigure_relay_status` 会发 `SetStatus` 通知 handler，但若 reservation 请求已在途中则太晚。
